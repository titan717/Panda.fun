# Decisions

Where the blueprint was ambiguous, impossible to reproduce literally, or referred to features outside this product's scope, the option closest to the blueprint was chosen and recorded here.

| # | Decision | Why |
|---|---|---|
| D-1 | The blueprint is JioHotstar; every brand mark is replaced with Panda (logo, name, colours kept as in the photos). | Own brand; layout and styling remain the blueprint's. |
| D-2 | TV rail "UPGRADE" pill → "UPDATE" (opens Check for Updates); mobile "UPGRADE" chip → "WHAT'S NEW". | No subscriptions; the slot keeps its position and style with a real function. |
| D-3 | "TADKA" tab → "NEW & HOT". | Required page; same tab slot and gradient pill. |
| D-4 | Sports, Connect Phone, Downloads, Cast, subscription/plan screens omitted; the subscription card in My Space becomes an app version/update card. | No such backend capabilities; showing them would be dead UI. |
| D-5 | Quality badges (4K/Dolby) omitted; ratings show TMDB score instead of IMDb. | Data not available from movieapi; no fake values. |
| D-6 | Typeface: Inter (self-hosted), closest open match to the blueprint's geometric sans. | Licensing. |
| D-7 | Layout by input and size: TV layout for TV devices (TV user agent or Android TV) and for desktops (fine pointer, window ≥ 900 × 480; mouse hover moves focus); touch-only devices — phones and tablets — use the mobile layout. `?layout=tv` forces TV. | Blueprint covers TV and phone only. |
| D-8 | TV rail shows 7 icons including New & Hot. | Required page needs a rail entry. |
| D-9 | Android bundle uses hash routing and relative asset base. | WebViewAssetLoader serves files, not an SPA server. |
| D-10 | Provider auto-next disabled; our own 10 s countdown handles next episode on all sources. | Consistent behaviour; works on the mirror too. |
| D-11 | Volume and transport commands only on CineSrc (postMessage API); Vidy reports progress events but takes no commands. | Provider protocol limits (PLAYER_COMPARISON.md). |
| D-12 | Trailers open in an in-app overlay (YouTube privacy-enhanced). CineSrc's internal episode navigation does not change our URL; we follow it via `nextepisode` events. | Keep Back behaviour predictable. |
| D-13 | Recent searches render as a text list (blueprint shows chips on mobile, list on TV — kept per platform). | Matches photos per platform. |
| D-14 | Notifications = "new release available" on launch only (opt-in). | No push backend; no tracking. |
| D-15 | 60+ stale remote branches were not merged: the "My Panda hub" work was already in `main`, the rest target the previous UI that was replaced by the rebuild. They remain for history but contain nothing valid to merge. | Mission rule "merge valid earlier work". |
| D-16 | Geometry recalibrated from full-resolution photos (tv2#1, tv2#9, tv1#2, tv1#6) — BLUEPRINT_SPEC §19. | Contact-sheet estimates were off by up to 30 %. |
| D-17 | Update checks read GitHub Releases directly (`/releases/latest`) on web and Android, cached 15 min; `update/latest.json` removed. | One source of truth; stays within GitHub's anonymous rate limit. |
| D-18 | Vercel production deploys through the existing Git integration (project `mypanda`, team `titan717s-projects`) on every push to `main`. The CLI token in the build sandbox is not authorised for that team scope, so CLI deploys are not used. | Same result (production from `main`), no extra credentials. |
| D-19 | One APK serves phones, tablets and Android TV (`leanback` optional, touchscreen not required). | Single release asset for the updater. |
| D-20 | Release versioning: stable `MAJOR.MINOR.PATCH`, `versionCode = 1236 + run number` so it is always above the old beta builds. | Lets existing beta installs upgrade in place. |
| D-21 | The API base accepts only `*.vercel.app` hosts or localhost; anything else falls back to `https://apikinoma.vercel.app/api/v1`. | Guarantees no stale URL of the retired host can come back through env vars. |
| D-22 | The mission names `vidsty.st`, which does not resolve (NXDOMAIN). The second source is `vidy.st`, the same `.st` embed family already used by movieapi. No `vidsrc.*` lookalikes are used. | Closest working match to the brief. |
| D-23 | Drive files `1KaWgZ8…` and `1yOYmIgd…` (tvnewblueprint.pdf) are byte-identical (same md5) — treated as one blueprint. | Avoids duplicate checklist entries. |
| D-24 | The Android renderer-crash callback is the only platform API whose name contained the retired host's name; the diagnostic string is renamed "WebView renderer crash" and, from v1.1.7, the callback lives in `CrashSafeWebViewClient.java` with an escaped capital R (D-90). | The retired hosting provider is fully removed; the platform API name cannot change. |
| D-25 | Iframe embeds expose no video frames or audio/subtitle track lists, so the seek strip shows timestamps over the backdrop and Audio & Subtitles shows only what the source reports. | Show controls only where the source exposes them (§6). |
| D-26 | Vercel production deploys of `mypanda` succeed from `main`, but its `*-titan717s-projects.vercel.app` URLs are behind Vercel Deployment Protection and `mypanda.vercel.app` belongs to another account. The build sandbox has no team-scoped Vercel access to add a public domain, so the repo homepage points to the latest GitHub Release (the APK bundles the web app). movieapi Git deployments are now enabled so `main` goes live on `apikinoma.vercel.app`. | Users get a working install path; nothing points at a site we don't own or at the retired host. |
| D-27 | Preferences are per profile except device-level keys (layout, Kids PIN, update notification state). Trailer sound, volume, delay and autoplay belong to the profile. | §4.B/§4.E "persist per profile". |
| D-28 | The Android app plays trailers through the YouTube IFrame player inside the WebView (with `mediaPlaybackRequiresUserGesture=false`) instead of the native YouTube Android Player library. That library is deprecated, needs a Google API key and a native view that cannot be layered under the web UI's gradients, focus and crop. | Closest working match to §4.B with one code path on every device. |
| D-29 | No reliable public source of direct studio trailer files exists for the catalogue — TMDB lists only YouTube/Vimeo keys and studio CDNs are unlisted and change. Trailers use YouTube keys ranked official trailer → teaser → other, up to 3 per title as fallbacks. | §4.B "research direct trailer files" — researched, not available. |
| D-30 | The Who's watching wall uses the new `GET /panda/wall` endpoint (up to 120 unique trending posters, w185) and falls back to weekly trending. Each column gets its own slice so no poster repeats on screen; the slice is drawn twice for a seamless loop. | §4.D. |
| D-31 | Trailer playback cannot be verified from the build sandbox: YouTube refuses embeds from datacenter IPs ("This video is unavailable", error 150/153). The engine is verified for staging, stop-on-move, one-at-a-time and fallback (unit tests + `scripts/qa-trailer-flow.mjs`); a failed embed falls back to the next key, then to the backdrop. | Honest record; behaviour degrades to the blueprint backdrop. |
| D-32 | Player quality options follow the blueprint labels: Auto (no hint), 4K → `quality=2160`, Full HD → 1080, HD → 720, Data Saver → 480. CineSrc treats the value as a preference and falls back to the closest available stream. Saved per profile. | TV PLAYER §20.9. |
| D-33 | CineSrc and Vidy expose no subtitle or audio-track API (cinesrc.st/docs lists only play/pause/seek/volume/mute/rate). The Audio & Subtitles panel keeps the blueprint's two columns: Audio = Original / Sound off (real mute command); Subtitles = Off / "Choose in source player", which reloads the embed at the same position with its native controls so the embed's own track menu is reachable. | No fake track lists (§1 no placeholders). |
| D-34 | The source switcher lives in the Quality panel as a "Source" group, because the blueprint has no separate source control and Quality is the closest playback-source setting. | §6 source switcher inside blueprint layout. |
| D-35 | "Report an Issue" posts `{type, tmdbId, season, episode, source, issue, position}` to `POST /api/v1/panda/report` (sendBeacon, logged server-side, 202) and then acts: "Video won't play" / "Wrong title" switch to the next source at the same position; "Out of sync" / "Subtitles" open the native source controls. | Report must do something useful, not be a dead button. |
| D-36 | The opening advisory ("Rated {certification}" with the cyan bar) uses genres as the descriptor line, since the catalogue has no content-descriptor data. | §20.6 closest available data. |
| D-37 | Production builds run on Preact's React-compatible runtime (`preact/compat`, aliased in `vite.config.ts`); unit tests keep real React. The app uses only standard hooks, portals, `lazy`/`Suspense` and `useSyncExternalStore`, all supported. This removes ~41 KB gzip from every cold start, which matters most on low-end Android TV boxes. The full e2e suite (92 tests, TV + mobile + tablet) passes on the Preact build. | §2/§8 "load extremely quickly". |
| D-38 | Every launcher icon, the adaptive icon, the TV banner (320×180 / 480×270 / 640×360), PWA icons, favicon and the native cold-start window are generated by `scripts/gen-brand.mjs` from the Panda mark on the blueprint splash gradient (§2). This replaces the leftover Kinoma "K" and empty ring artwork. The adaptive icon has no monochrome layer because a tinted silhouette of the face would be an unreadable blob. | §1.11 Panda mark everywhere; §7 icons and banner. |
| D-39 | "What's New" appears once, as a right-side sheet on TV and a bottom sheet on mobile, the first time a newer version starts. A fresh install records its version silently. Notes come from the GitHub Release section "## What's new in X" and are cached on the device; Settings › What's New shows them any time. | §7 "What's New after an update"; G-6. |
| D-40 | Emulator verification (icon, banner, splash, launch, first screen) runs in GitHub Actions (`emulator-check.yml`, Android TV API 34 + phone API 34) because the build sandbox has no KVM. Screenshots are uploaded as run artifacts. | §7 "emulator screenshots". |
| D-41 | The expanded row card shows the title's own backdrop (w780, requested only after focus rests for 350 ms) under a left-to-right navy glass scrim, with the poster hidden; until the backdrop decodes, the poster stays underneath. | Blueprint tvpanda i-003 (BLUEPRINT_SPEC §6.3). |
| D-42 | Inside the Android app the native bridge (`KinomaNative.isTV()`, UI mode + Leanback feature) decides the layout, and the WebView adds the "Android TV; Leanback; SmartTV" tokens only on televisions. Before, every phone APK opened in the TV layout. Browsers still use the user agent and pointer/size test. | §2 "MOBILE very good; protect it"; found on the phone emulator in the v1.0.5 check. |
| D-43 | Rating badges show the TMDB vote average with a star, not "IMDb 7.8": apikinoma has no IMDb rating, and labelling a TMDB score as IMDb would be fake data (G-8). | §1 no fake data. |
| D-44 | Display settings: TV screen size 90/95/100 % (one transform on `#root`), text size Default/Large/Larger (×1, ×1.15, ×1.3 through a build-time PostCSS plugin that multiplies every absolute font-size by `--fs`), Reduce motion (also honoured by every animation hook) and High contrast (a white 4 px focus border with a yellow glow).
